Ещё варианты — самое удобное и красивое

Тут не Rich Message-блоки, а обычные фичи Bot API уровня sendMessage — инлайн-кнопки, реплай-цепочка, <pre>, tg-spoiler. нативная фича Bot API — это не экспериментальная схема как Rich-блоки выше, это часть API многие годы, риска почти нет, но нужно немного логики на бэкенде (обработка callback от кнопки, хранение message_id первого алерта инцидента для реплая).

GКнопки действий под сообщением нативная фича Bot API

Самое полезное из всего списка: реальные тапаемые кнопки (reply_markup.inline_keyboard) — открыть дашборд без копирования ссылки, подтвердить, что видел алерт (Ack), или замьютить канал на час прямо из чата. Не Rich Message — обычный параметр sendMessage, поддерживается везде без исключений.

KРеплай-цепочка вместо разрозненных сообщений в проде

Все алерты того же инцидента одного сервера (ongoing/escalated/resolved) отправляются как reply (reply_parameters.message_id) на первое сообщение ("opened") — визуально собираются в один тред вместо расползания по чату отдельными несвязанными сообщениями. Корень треда хранится в Redis по (channel_id, server_id) с TTL 24ч; если Redis недоступен или ключ истёк — просто шлётся обычное несвязанное сообщение (не ломает доставку). На resolved тред закрывается. Только для событий вида opened/ongoing/escalated/resolved — разовые события (IP/сертификат/контент изменились) не тредятся.

✨Тренд + переход статуса + ошибка первой + номер инцидента + кнопки идея

Что подтверждённо работает в Telegram сегодня (проверено вручную на живом боте): обычный форматированный текст (<b>, <code>, <a>, <blockquote expandable>) — варианты №1, №5, №6; и Rich Message-таблица с плоскими текстовыми ячейками (sendRichMessage, cells: [[{"text":...}]]) — вариант №2.
Что появилось в свежей версии Bot API, но не проверено (карточки №3, №4, №7, №8, №9): официальные классы InputRichBlockList/ListItem, InputRichBlockDivider, InputRichBlockSectionHeading, InputRichBlockFooter, InputRichBlockDetails, InputRichBlockPullQuotation и медиа-блоки (Photo/Map/др.) + поле media у InputRichMessage. Раньше похожие блоки (details, самодельный чек-лист) либо схлопывались пустыми, либо давали 400 — теперь это задокументированная часть схемы, но перед вкруткой в dispatcher.py каждый блок нужно прогнать через тестовый канал так же, как в своё время таблицу (см. историю git — несколько вариантов cells 400'лись до рабочего).
Осознанно не включено: голосовые заметки (InputMediaVoiceNote) — звуковой алерт технически возможен, но добавит только уведомление-усталость без пользы для мониторинга; markdown-таблицы через InputRichMessageMedia/media — избыточно, раз обычный table-блок уже работает.
