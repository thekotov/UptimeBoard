Варианты заголовка (на базе текущего формата)

Тело сообщения — как сейчас (Проба / Где / Ошибка / Длится / Время / ссылка), меняется только первая строка (или первые 1–2 строки): чтобы сразу, без чтения списка полей, было видно что случилось, имя сервера и его IP.

1Как сейчас (для сравнения)

Статус есть, но сервер и IP нужно искать в строке «Сервер» — при беглом просмотре списка сообщений не сразу понятно, какой хост упал.

2Статус + сервер + IP в одной строке

Максимально плотно — всё, что нужно для «выхватить взглядом», влезает в первую строку. Остальное как раньше, но строка «Сервер» из тела убрана (уже есть в заголовке).

3Статус отдельно, сервер+IP крупно под ним

Статус — как заголовок сообщения (что случилось), а сразу под ним — жирным имя сервера и IP, как «подзаголовок». Дальше тело без изменений (строка «Сервер» убрана — не дублируем).

С цитированием (Telegram <blockquote>)

Telegram поддерживает markdown-цитаты — визуально это блок с полосой слева и приглушённым фоном, выделяется среди обычного текста без лишних тегов/эмодзи. Пробуем спрятать в цитату детали или ошибку, чтобы заголовок «что случилось / сервер / IP» бросался в глаза первым.

7Заголовок открытый, все детали — в цитате

Статус + сервер + IP — обычным текстом сверху, всё остальное (проба/где/ошибка/длится/время) — одним цитируемым блоком. Глазами цепляется только заголовок, детали читаются по желанию.

Новое из Bot API 10.1/10.2 «Rich Messages» (июнь–июль 2026)

По статье на Хабре и чейнджлогу Bot API: Telegram добавил блочный формат Rich Messages — таблицы, чек-листы, схлопываемые <details>-блоки, сноски, спойлеры, кастомные эмодзи, эффекты сообщений. уже сейчас — работает через обычный sendMessage + parse_mode=HTML, как всё выше. новый API — только через новый метод sendRichMessage с блоками (InputRichBlockTable, InputRichBlockParagraph и т.д.) — это отдельная реализация в _send_telegram(), не совместимая с текущим HTML-текстом «в лоб».

12Нативный <details> вместо цитаты новый API

Тот же принцип, что и вариант №9 (заголовок открыт, детали свёрнуты), но через настоящий раскрывающийся блок Rich Messages — заголовок сворачиваемой секции можно задать текстом («Детали»), а не универсальной стрелкой цитаты.

17Сноска на статус-страницу вместо инлайн-ссылки новый API

Rich Messages поддерживают сноски (footnotes) — вместо «🔗 Открыть статус-страницу» в конце текста ссылка становится верхним индексом [1] у заголовка, а сама ссылка — компактной сноской внизу. Меньше визуального шума в первой строке.

🟠 Деградация — api-node04 · 158.160.60.150 [1] Проба: Health Check · HTTP Ошибка: timed out Длится уже: 0 с Время: 11.08.2026 13:02:21 UTC [1] status.chatapp.team/production16:02
Во всех вариантах, кроме №6, строка «Сервер» из тела убирается, чтобы не дублировать то, что уже видно в заголовке — имя и IP переносятся в первую строку(и), остальные поля (Проба/Где/Ошибка/Длится/Время/ссылка) без изменений.
Цитаты (7–11) рендерятся тегом <blockquote> (для №9 — <blockquote expandable>), реальная полоса и оттенок фона в Telegram зависят от темы клиента, но структура сообщения будет такой же.
№12–15, 17 (Rich Messages) требуют отдельного пути в _send_telegram() — новый метод sendRichMessage и блочная структура вместо HTML-строки; №13 и №16 работают уже сейчас поверх текущего sendMessage/parse_mode=HTML, без переделки транспорта.
Скажи номер понравившегося — поправлю _header() / _build_messages() (и, если нужно Rich Messages, _send_telegram()) в backend/app/alerts/dispatcher.py под него.
