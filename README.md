# Monitoring Dashboard

Сервис статус-страниц для мониторинга доступности веб-приложений: пробы ICMP/TCP/HTTP/TLS,
агрегация статусов, инциденты, алерты и публичные дашборды в реальном времени (SSE).

## Модель

```
Page (публичный дашборд, /status/<slug>)
 └── Service        агрегированный статус
      └── Server     агрегация по своим пробам
           └── Probe (icmp | tcp | http | tls)
```

Статус агрегируется снизу вверх: `up` / `degraded` / `down` / `unknown`. Сервер берёт
худший статус среди проб; сервис/страница — `up`, если все потомки `up`, `down` — если
все `down`, иначе `degraded`.

## Стек

FastAPI + SQLAlchemy + Alembic (`api`), планировщик проб на APScheduler (`worker`),
PostgreSQL, Redis pub/sub, фронтенд на React + Vite за nginx (он же проксирует `/api`).

## Быстрый старт

```bash
cp .env.example .env          # отредактируйте JWT_SECRET / ADMIN_PASSWORD
docker compose up --build     # postgres, redis, api, worker, frontend

# админ-пользователь + демо-страница (идемпотентно)
docker compose run --rm api python -m scripts.seed
```

- **Демо-дашборд:** http://localhost:8080/status/demo
- **Админка:** http://localhost:8080/admin  (вход по `ADMIN_EMAIL` / `ADMIN_PASSWORD`)
- **API-документация:** http://localhost:8000/docs

## Типы проб

Настраиваются для каждой пробы в админке (JSON-поле `config`):

| Тип | Ключи |
|------|-------------|
| `http` | `url`, `method`, `expected_status`, `expected_body_substr`, `follow_redirects` |
| `tcp`  | `port` |
| `icmp` | `count`, `packet_size` |
| `tls`  | `port`, `warn_days` — доступность + срок действия сертификата; `track_cert_change` (алерт при смене сертификата) |
| `http` (доп.) | `headers`, `basic_user`/`basic_pass`, `bearer_token`, `expected_body_regex`, `json_path`/`json_expected`, `check_cert`/`warn_days` (отслеживание SSL-сертификата) + `track_cert_change` (алерт при смене сертификата), `track_ip` (алерт при смене IP хоста) |
| `heartbeat` | `grace_sec` — пассивная: крон шлёт `GET/POST /api/ping/<token>`; нет пинга за `период + grace` → `down` |

Также: **`failure_threshold`** (открывать инцидент только после N подряд сбоев — защита
от дребезга) и **`latency_degraded_ms`** (помечать `degraded` при медленном ответе).

**Пауза пробы** (⏸ в редакторе) — проба не проверяется, помечается «На паузе» и
**не учитывается** в статусе сервера/сервиса; открытый инцидент при постановке на паузу
автоматически закрывается. Возобновление — ▶.

ICMP использует raw-сокеты — воркеру выдаётся `NET_RAW` (см. `docker-compose.yml`).

## Редактор страницы

Иерархия страницы (сервисы → серверы → пробы) редактируется на `/admin/pages/<id>`:

- **Перетаскивание** — сортировка сервисов, серверов и проб мышью (ручка ⠿). Пробу можно
  перетащить **в другой сервер**, в том числе в пустой. Порядок сохраняется на бэкенде (`order`).
- **Инлайн-переименование** — двойной клик по имени сервиса/сервера/пробы.
- **Клонирование** (⧉) — копия пробы, сервера (со всеми пробами), сервиса или всей страницы
  целиком вместе с вложенной иерархией.
- **Экспорт/импорт страницы** — выгрузка в переносимый JSON и загрузка обратно.
- **Массовые действия над пробами** — отметить чекбоксами и разом включить/выключить,
  проверить сейчас или удалить.
- **«Проверить сейчас»** (отдельная проба) и **тест конфигурации** пробы без сохранения.
- **Свернуть/развернуть** сервисы; живая инлайн-валидация форм (занятость slug, формат URL/портов).

Список страниц поддерживает поиск и группировку (`group_name`). В шапке админки — индикатор
живости воркера (опрос `/api/health/worker`).

## Алерты

Каналы в **Админка → Каналы алертов** (`/admin/alerts`): **Telegram** (`bot_token` + `chat_id`),
**Webhook** (`url`, опц. `secret_header`/`secret_value`), **Email/SMTP**. Канал можно нацелить
на одну страницу или на все, протестировать связь и задать свой шаблон сообщения
(`{event}`, `{verb}`, `{probe}`, `{host}`, `{status}`, `{error}`).

События инцидента: **`opened`** (падение), **`ongoing`** (повтор, если `ALERT_REPEAT_MIN>0`),
**`escalated`** (эскалация) и **`resolved`** (восстановление) — канал можно подписать только на
нужные. По умолчанию воркер шлёт одно «opened» и одно «resolved» на инцидент.

- **Группировка «шторма»** — `down`/`resolved` для проб одного сервера объединяются в окне
  `ALERT_GROUP_WINDOW_SEC` (по умолч. 60с): падение всего сервера = один алерт, а не N.
- **Эскалация** — у канала `escalate_after_min`: `0` — алерт сразу; `>0` — только если
  инцидент висит дольше указанного времени (эскалация дежурному/в другой канал).
- **Доставка** — неудачная отправка повторяется (`ALERT_RETRY_ATTEMPTS` с экспоненциальной
  задержкой `ALERT_RETRY_BACKOFF_SEC`).

**Инциденты** (журнал в редакторе): можно **подтвердить** (ack) — инцидент остаётся открытым,
но затихает (без повторов/эскалации) до восстановления; снять подтверждение; удалить отдельный
инцидент или очистить историю (все/только закрытые).

**Окна обслуживания** (🛠 в редакторе) — на время окна по странице **не открываются инциденты и
не шлются алерты**, а на публичной странице висит баннер «идёт обслуживание».

**Объявления** (📢 в редакторе) — информационные баннеры на публичной странице с временным
окном и уровнем (инфо/предупреждение); не привязаны к пробам и **не** подавляют алерты (в отличие
от окон обслуживания).

## Публичная страница

`/status/<slug>` обновляется в реальном времени по SSE (`/api/public/pages/<slug>/stream`).
Показывает агрегированный статус, аптайм-таймлайн за `24h / 7d / 30d / 90d` (даунсэмплинг по
бакетам), журнал инцидентов и детализацию по пробе (последние проверки + латентность относительно
медианы). Есть поиск, фильтр по статусу, переключатель плотности и авто-сворачивание здоровых
сервисов.

## Конфигурация (`.env`)

| Переменная | Назначение |
|-----|---------|
| `DATABASE_URL`, `REDIS_URL` | строки подключения |
| `JWT_SECRET`, `JWT_EXPIRE_MIN` | авторизация админа |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | сидируемый админ |
| `RESULT_RETENTION_DAYS` | срок хранения результатов проб |
| `PROBE_DEFAULT_INTERVAL`, `PROBE_DEFAULT_TIMEOUT` | дефолты новых проб |
| `WORKER_MAX_THREADS` | параллельных проверок в воркере (по умолчанию 50) |
| `ALERT_REPEAT_MIN` | повтор алерта, если инцидент висит дольше N мин (`0` — выкл.) |
| `ALERT_GROUP_WINDOW_SEC` | окно группировки «шторма» алертов сервера (по умолч. 60с) |
| `ALERT_RETRY_ATTEMPTS`, `ALERT_RETRY_BACKOFF_SEC` | ретраи доставки алерта и базовая задержка |
| `STALE_FACTOR`, `STALE_GRACE_SEC` | порог «протухания» пробы: `interval × factor + grace` |
| `CORS_ORIGINS` | `*` или список origin'ов через запятую |

Прочие настройки (`JWT_ALGORITHM`, `WORKER_HEARTBEAT_SEC`/`WORKER_STALE_SEC` для dead-man
проверки воркера, имена Redis-каналов) — в [`backend/app/config.py`](backend/app/config.py).

## Разработка

```bash
# Бэкенд
cd backend && python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload    # API
python -m app.worker             # планировщик
pytest                           # тесты (агрегация + пробы)

# Фронтенд
cd frontend && npm install
npm run dev                      # Vite на :5173, проксирует /api -> :8000
```
